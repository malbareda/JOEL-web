# 1.3. L'app `judge/`: models, vistes i admin

> Autor d'aquesta documentació: **Edgar**

`judge/` és l'única app de Django d'aquest projecte, i conté pràcticament tota la lògica de
producte. Aquest document cobreix les tres capes que qualsevol funcionalitat travessa: el model de
dades, les vistes que l'exposen al navegador, i la seva gestió des de l'admin.

## `judge/models/` —la capa de dades

- **`__init__.py`**: el punt d'agregació —reexporta tots els models dels fitxers individuals, i
  registra el seguiment d'historial (`django-reversion`) per als models principals (vegeu
  [4](../04-particularitats-programacio/README.md)).
- **`choices.py`**: taules estàtiques d'opcions (fusos horaris, temes de l'editor de codi Ace,
  motors de renderitzat matemàtic).
- **`problem.py`** (el fitxer més gran): `ProblemType`, `ProblemGroup` (taxonomia/temes), `License`,
  el model central **`Problem`** (enunciat, punts, límits de temps/memòria, configuració de
  checker, control de visibilitat, relacions amb autors/curadors/provadors), `ProblemTask`
  (l'agrupació personalitzada "Tasca"), `ProblemTranslation`, `ProblemClarification`,
  `LanguageLimit` (límits per llenguatge), `Solution` (editorial), i **`Guide`/`GuideTranslation`**
  (els problemes guiats, [2.2](../02-sistemes/2.2-problemes-guiats.md)).
- **`submission.py`**: **`Submission`** (el registre central d'una correcció), `SubmissionSource`
  (el codi font, separat per mantenir la taula principal prima), `SubmissionVote`,
  `SubmissionTestCase` (resultat per cas).
- **`contest.py`**: `ContestTag`, **`Contest`**, `ContestParticipation`, `ContestProblem`,
  `ContestSubmission`, `Rating`, `ContestMoss` —detallats a [2.3](../02-sistemes/2.3-concursos.md).
- **`profile.py`**: `Achievement`/`AchievementObtained` (gamificació,
  [2.4](../02-sistemes/2.4-gacha-i-personalitzacio.md)), **`Organization`**
  ([2.5](../02-sistemes/2.5-organitzacions-mode-professor.md)), **`Profile`** (l'extensió de
  l'usuari de Django: punts, *rating*, fus horari, preferències, testimoni d'API, estat de 2FA),
  `WebAuthnCredential`, `OrganizationRequest`.
- **`runtime.py`**: `Language` (un llenguatge de programació), `RuntimeVersion` (versió concreta
  reportada per cada jutge connectat), `Judge` (un jutge registrat: nom, clau d'autenticació, estat
  de connexió, llenguatges suportats).
- **`problem_data.py`**: `ProblemData`/`ProblemTestCase` —les dades de correcció d'un problema,
  detallades a [3.1](../03-flux-intern/3.1-creacio-problema.md) i
  [5.6](../05-sistemes-mecanics/5.6-carpeta-problemes.md).
- **`comment.py`**: `Comment` (fil de comentaris, basat en `mptt`, adjuntable a qualsevol contingut
  via una clau de pàgina de text), `CommentVote`, `CommentLock`.
- **`interface.py`**: `MiscConfig` (configuració clau/valor editable des de l'admin), `NavigationBar`
  (l'arbre del menú principal del lloc), `BlogPost`.
- **`message.py`**: missatgeria privada entre usuaris.
- **`ticket.py`**: el sistema de tiquets/aclariments.

**Relacions clau**: `Submission` apunta a `Problem`, `Profile` i `Language`; `ContestSubmission`
enllaça `Submission` amb `ContestParticipation`; `ProblemData`/`ProblemTestCase` pengen d'un
`Problem`; `Profile` té una relació un a un amb el `User` de Django. `Comment`/`Ticket` s'enganxen a
altres models de manera genèrica (per clau de text o per tipus de contingut), permetent
reutilitzar-los sobre problemes, concursos o entrades de blog sense relacions dures.

## `judge/views/` —la capa de vistes

Organitzada en un fitxer per àrea funcional, amb una correspondència gairebé directa amb els blocs
de `dmoj/urls.py`:

- `problem.py` (el més gran): tot el que envolta veure/resoldre un problema —detall, editorial,
  guia, PDF, clonatge, enviament/reenviament, estat de resolució, i les vistes paral·leles per a
  "Tasques".
- `problem_data.py`/`problem_manage.py`: l'editor de dades de test i la gestió massiva de
  submissions (*rejudge*, recorrecció).
- `submission.py`: la pàgina d'estat d'una submissió amb actualització en viu, vot, avortament,
  marcatge (pistes).
- `contests.py` (el segon més gran): tot el cicle de vida d'un concurs.
- `organization.py`, `user.py` (inclou el gacha), `ticket.py`, `two_factor.py`, `register.py`,
  `select2.py` (autocompletat), `stats.py` (dades per a gràfics), `status.py` (estat de
  jutges/llenguatges), `ranked_submission.py`, `preview.py` (vista prèvia de Markdown per tipus de
  contingut), `widgets.py` (utilitats AJAX diverses), `blog.py`, `comment.py`, `language.py`,
  `license.py`, `mailgun.py`, `error.py`, `tasks.py` (sondeig de progrés de Celery).
- `api/api_v1.py`, `api/api_v2.py`: les dues generacions de l'API pública de només lectura.

## `judge/admin/` —la capa d'administració

Un `ModelAdmin` personalitzat per a cada model rellevant, registrat centralment a
`judge/admin/__init__.py`: `ProblemAdmin`, `ContestAdmin`/`ContestParticipationAdmin`,
`ProfileAdmin`, `SubmissionAdmin`, `JudgeAdmin`/`LanguageAdmin`, `OrganizationAdmin`,
`TicketAdmin`, `CommentAdmin`, `AchievementAdmin`, `BlogPostAdmin`, i els admins de taxonomia
(`ProblemGroupAdmin`/`ProblemTypeAdmin`/`ProblemTaskAdmin`). Cadascun aporta llistes personalitzades,
filtres, formularis en línia (per exemple, límits per llenguatge dins la fitxa d'un problema) i
accions en bloc (com les de fer un problema públic/privat, que disparen recorrecció de puntuacions
via Celery).
