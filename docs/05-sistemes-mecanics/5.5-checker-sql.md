# 5.5. El checker SQL: problemes de consultes a bases de dades

> Autor d'aquesta documentació: **Edgar**

## Què resol

Permet crear problemes on l'alumne no envia codi en un llenguatge de programació, sinó **una
consulta SQL**, que es corregeix comparant el seu resultat amb el d'una consulta de referència
sobre una base de dades SQLite real. És totalment nou en aquest fork —no existeix res de semblant
al DMOJ original.

## Com "s'envia" SQL sense un llenguatge nou

No calia inventar cap mecanisme d'enviament nou: l'alumne escriu la seva consulta al quadre de codi
normal, triant el llenguatge **`TEXT`**, l'executor del qual és literalment `cat`
(secció [2.7](../02-sistemes/2.7-jutge-intern.md)). Això vol dir que `process_output` que rep el
checker és, byte a byte, el text que l'Edgar ha escrit — no cal compilar ni interpretar res.

## On viu el checker: `dmoj/checkers/sql.py`

Un fitxer nou (no present al DMOJ de referència). Lògica completa:

### 1. Resolució del fitxer de base de dades

El checker rep `problem_id` (que el grader sempre passa) i el resol amb la mateixa funció
(`get_problem_root`) que fa servir tot el motor per trobar la carpeta d'un problema. Hi ajunta
`db_file` (un argument de l'`init.yml`, per defecte `miniwind.db`) per obtenir la ruta completa. Si
no la troba, ho intenta com a ruta absoluta.

### 2. Seguretat: només `SELECT`

`_security_check()` passa la consulta a majúscules, elimina comentaris SQL (`--...` i `/*...*/`), i
**rebutja** qualsevol consulta la paraula clau inicial de la qual sigui:

```
INSERT, UPDATE, DELETE, DROP, ALTER, CREATE, TRUNCATE, EXEC, EXECUTE,
ATTACH, DETACH, PRAGMA, VACUUM, REINDEX
```

També rebutja diverses sentències separades per punt i coma (una sola consulta, i que sigui de
lectura).

### 3. Execució: només lectura, dues vegades

`_execute_sql()` obre la base de dades en **mode de només lectura** a nivell del propi SQLite
(`sqlite3.connect('file:%s?mode=ro' % db_path, uri=True)`) i, a més, executa `PRAGMA query_only = ON`
abans de res —una segona xarxa de seguretat, per si la llista negra de paraules clau es pogués
evitar d'alguna manera. Aquesta mateixa funció s'usa per executar **tant la consulta de referència
del professor com la de l'alumne**, sempre sobre la mateixa base de dades.

### 4. Comparació de resultats (`_compare_results`)

1. El **nombre de columnes** ha de coincidir sempre (si no: "Wrong number of columns").
2. Els **noms** de columna només es comparen si l'argument `compare_columns=True` (per defecte
   `False` — així `SELECT nom FROM t` i `SELECT t.nom AS x FROM t` es consideren equivalents).
3. El **nombre de files** ha de coincidir.
4. Si `order_matters=True` (per defecte `False`), les files es comparen en l'ordre original; si no,
   totes dues llistes de files s'ordenen abans de comparar-les —és a dir, **per defecte l'ordre de
   les files no importa**.
5. Cel·la a cel·la: `None` només és igual a `None`; els nombres decimals es comparen amb una
   tolerància (`float_tolerance`, per defecte `0.001`); la resta, igualtat exacta.
6. Si tot coincideix: `CheckerResult(True, punts_del_cas, "")`. Si no, es retorna `CheckerResult`
   amb `False` i un motiu concret ("Wrong number of columns", "Row N differs", consulta amb error de
   sintaxi, base de dades no trobada, etc.) —motiu que l'alumne veu com a *feedback*.

## Com es configura des de l'aplicació web

Un professor puja el fitxer `.db` (SQLite) a través del camp `sql_db` del formulari de dades del
problema (`ProblemDataForm`, secció [3.1](../03-flux-intern/3.1-creacio-problema.md)), i marca el
checker del problema (o d'un cas concret) com a `sql`. Quan es desa, el compilador de dades
(`ProblemDataCompiler.make_init()`) detecta `checker == 'sql'` i, en lloc d'exigir un fitxer
d'entrada (com fa amb qualsevol altre problema), només exigeix el fitxer de sortida (`.out`, que
conté el text de la consulta *correcta*), i escriu a l'`init.yml`:

```yaml
checker:
  name: sql
  args:
    db_file: miniwind.db
```

`miniwind.db`, l'arxiu `.zip` (amb el `.out` de referència) i l'`init.yml` acaben tots junts a
`/judge/<codi_problema>/` —vegeu [5.6](5.6-carpeta-problemes.md).

## Exemple real al servidor

A `/judge/provasql2/` hi ha exactament aquesta estructura: `q1.zip`, `miniwind.db`, i un
`init.yml` que referencia `checker: {name: sql, args: {db_file: miniwind.db}}`. També existeix, com
a rastre d'un experiment anterior, `/judge/provasql/`, que fa servir un checker *local al problema*
(`sql_checker.py`, carregat per nom de fitxer en lloc del mòdul compartit `sql`) —aquest camí
antic no forma part del sistema `CHECKERS` de l'aplicació web i no s'ha de fer servir per a
problemes nous; l'únic camí "de producció" és l'entrada `sql` del desplegable de checkers.
